# Kurikulum Penguasaan VM Terisolasi di Arch Linux (100% TUI)

Asumsi beban belajar: sekitar 8-10 jam per minggu. Kode lab (L1.1, L2.3, dst.) disiapkan sebagai ID untuk generate modul berikutnya.

| No | Nama Fase | Tujuan Akhir | Skill Kunci | Lab Utama | Validasi Lulus |
|----|-----------|--------------|-------------|-----------|----------------|
| 1 | **Fondasi Virtualisasi & Host Hardening** | Host Arch siap menjalankan VM, arsitektur KVM-QEMU-libvirt dipahami, dan permukaan serangan host minimal | Cek VT-x/AMD-V & IOMMU, modul `kvm`, instalasi stack minimal tanpa paket GUI, `qemu:///system` vs `qemu:///session`, polkit & grup, dasar nftables | **L1.1** Audit hardware & kernel (lscpu, `/dev/kvm`, dmesg IOMMU)<br>**L1.2** Instalasi stack headless minimal<br>**L1.3** Daemon libvirt di bawah systemd (socket activation)<br>**L1.4** Akses `virsh` non-root via polkit & grup<br>**L1.5** Baseline nftables host | `virt-host-validate qemu` semua PASS; `virsh list --all` jalan sebagai user non-root; tidak ada paket GUI terpasang |
| 2 | **QEMU/KVM Murni (Tanpa libvirt)** | Memahami VM sebagai satu proses QEMU, sehingga libvirt hanya menjadi pembungkus | `qemu-system-x86_64`, `qemu-img`, perangkat virtio, OVMF (UEFI), swtpm, QMP, serial console | **L2.1** Boot VM pertama dari CLI (`-nographic`)<br>**L2.2** `qemu-img`: create, convert, inspect (raw/qcow2)<br>**L2.3** Perangkat virtio (blk, net, rng, balloon) vs emulasi<br>**L2.4** UEFI OVMF + vTPM dengan swtpm<br>**L2.5** Kontrol runtime via QMP socket | Boot Arch minimal dengan satu perintah QEMU ber-virtio; shutdown & query status via QMP; semua flag bisa dijelaskan |
| 3 | **libvirt & virsh: Lifecycle & Domain XML** | Mengelola seluruh siklus hidup VM dan membaca/menulis domain XML | `virt-install` headless, `virsh define/edit/dumpxml`, `virt-xml`, storage pool & volume, `virt-top`, `virsh domstats` | **L3.1** `virt-install` headless (`--graphics none --console`)<br>**L3.2** Anatomi domain XML<br>**L3.3** Lifecycle: start, suspend, save/restore, autostart<br>**L3.4** Storage pool & volume (`pool-*`, `vol-*`)<br>**L3.5** Monitoring dengan `virt-top` & `domstats` | Provisioning 3 VM (Arch, Debian, cloud image) murni TUI; VM bisa dihapus dan dibangun ulang hanya dari file XML |
| 4 | **Storage, Image & Backup Engineering** | Mengelola disk VM secara efisien, bisa di-clone, di-snapshot, dan dipulihkan | qcow2 backing chain, snapshot & `blockcommit`, `virt-sysprep`, `virt-customize`, `virt-clone`, libguestfs, `qemu-nbd`, backup live | **L4.1** Golden image + overlay backing chain<br>**L4.2** Snapshot internal/external, `blockcommit`/`blockpull`<br>**L4.3** `virt-sysprep` + `virt-customize` + `virt-clone`<br>**L4.4** Edit disk offline (`guestfish`, `guestmount`, `qemu-nbd`)<br>**L4.5** Backup live & uji restore | 5 VM clone dari 1 golden image; restore dari backup terverifikasi checksum; file guest berhasil diambil tanpa mem-boot VM |
| 5 | **Networking & Isolasi Jaringan** | Mendesain topologi jaringan VM dengan batas isolasi yang terbukti | Mode network libvirt (isolated/NAT/routed), bridge & macvtap, nftables, `nwfilter`, `tcpdump` pada interface `vnet` | **L5.1** Network isolated, NAT, routed (`net-define`)<br>**L5.2** Bridge vs macvtap (systemd-networkd)<br>**L5.3** Topologi multi-segmen dengan VM router/firewall<br>**L5.4** `nwfilter` + nftables: anti-spoof, default-deny egress<br>**L5.5** Debug jaringan (`domiflist`, `tcpdump`, `bridge`) | Lab 3 segmen (DMZ/LAN/isolated) dengan matriks konektivitas yang dibuktikan `ping`/`nc` sesuai desain; VM isolated tidak bisa menjangkau host maupun internet |
| 6 | **Keamanan & Isolasi Lanjutan** | VM yang tidak tepercaya tidak bisa membahayakan atau mengganggu host | Hardening domain XML, cgroups v2 (`cputune`/`memtune`/`blkiotune`), seccomp sandbox, AppArmor (bila diaktifkan), Secure Boot, vTPM, enkripsi disk, `qemu:///session`, auditd | **L6.1** Hardening XML: buang USB/spice/VNC/sound, console serial-only<br>**L6.2** Confinement QEMU: cgroups, seccomp, AppArmor<br>**L6.3** Secure Boot + vTPM + enkripsi disk (qcow2 LUKS / LUKS di guest)<br>**L6.4** VM unprivileged via `qemu:///session` per user lab<br>**L6.5** Threat model, audit & logging | Threat model tertulis + checklist hardening; `stress-ng` di VM tidak membuat host kehabisan resource; `virt-host-validate` PASS penuh |
| 7 | **Otomasi, Troubleshooting & Capstone Multi-OS** | Mandiri total: membangun, merawat, dan memperbaiki VM apa pun dari OS mana pun lewat skrip | cloud-init (NoCloud), Windows guest headless (virtio-win, unattended), libvirt hooks, unit systemd, Bash automation, diagnosis via log & QMP | **L7.1** Provisioning otomatis cloud-init (Arch/Debian)<br>**L7.2** Windows guest headless: autounattend, virtio-win, akses SSH/WinRM<br>**L7.3** Skrip Bash + libvirt hooks + unit systemd (autostart, shutdown berurutan)<br>**L7.4** Drill troubleshooting: boot gagal, disk penuh, network mati, hang<br>**L7.5** Capstone: infrastruktur 4+ VM multi-OS, build & destroy dengan satu perintah | Skrip capstone idempotent membangun seluruh lab dari nol (target di bawah 15 menit); 5 skenario troubleshooting lulus berbatas waktu; runbook terdokumentasi |

**Catatan Windows (L7.2):** installer Windows butuh display grafis, jadi tidak ada konsol teks murni seperti Linux. Pendekatan TUI-nya adalah instalasi *unattended*, akses lanjutan via SSH/WinRM, dan `virsh screenshot` yang ditampilkan di terminal dengan viewer berbasis karakter.
